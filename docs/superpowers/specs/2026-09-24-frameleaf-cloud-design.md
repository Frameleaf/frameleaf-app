# Frameleaf Cloud design (approved 2026-09-25)

Status: approved design record for the Frameleaf Cloud program. Repository Markdown is authoritative and is mirrored to Confluence space FR. Cloud-side internals (identity provider, relay, billing, the hosted ML service) are specified in the Frameleaf Cloud space (FC) and, once bootstrapped, in the `Frameleaf/frameleaf-cloud` repository; this document records the decisions, the contracts the self-hosted server implements, the sequencing and the acceptance gates. Customer-facing copy always says "Frameleaf Cloud".

## 1. Summary

Frameleaf (this immich fork, Jira FL) stays fully self-hostable with no account and no license. This
program adds an optional Plex.tv / Home-Assistant-Cloud style layer:

- **Frameleaf account** (new SaaS, repo `Frameleaf/frameleaf-cloud`, NestJS + Postgres on VPS containers)
  acting as the OpenID Connect provider for self-hosted servers, owning instances, subscriptions, licenses,
  the AI Wallet and per-service grants. Linking lets people use their library from the Frameleaf mobile apps from
  anywhere.
- **Remote access**: blind SNI relay (cloud never decrypts) + per-server wildcard certificate obtained on
  the instance + UPnP/NAT-PMP/PCP direct connect; every remote user signs in with a Frameleaf account,
  enforced by the instance (which stays the auth authority); optionally a custom public hostname on the owner's
  domain (CNAME to the relay name, certificate issued and renewed on the server).
- **Licensing**: our own entitlement service (Stripe = billing truth, Ed25519-signed license certificates),
  a cloud subscription (relay + backup) and one-time supporter keys (badge + 20 % off Frameleaf Cloud plans; AI
  credit is never discounted). Plan and Licence are separate settings pages.
- **Frameleaf Cloud ML** (proprietary, clean-room): advanced descriptions, Topaz-class upscaling, video
  restoration, Studio AI and Smooth motion frame interpolation, run only on serverless GPU workers (no on-demand pods),
  user-selected model per job from a light → heavy ladder, billed by metered GPU time to a prepaid **AI Wallet**. It **replaces the fork's previous GPU-provider integration**; the OSS ML service stays
  the local/LAN destination. Studio exports render locally only (this server or a LAN worker); Smooth motion at export
  may still use Frameleaf Cloud as its own job. Customer-facing copy never says "the GPU provider", only "Frameleaf Cloud".
- **Activity** shows every job (edits, exports, AI jobs, background server work, cloud backup runs) with stages
  Queued → Starting → Running → Done / Failed / Cancelled / Paused and an In progress section.
- **Cloud backup**: a native content-addressed agent (SHA-256, one object per unique file, only new or changed
  files ever upload, duplicates never), one dedicated bucket per server (never mixed), Wasabi SSE-C with a
  per-bucket key that the server generates and stores, or that the user generates and downloads (kept on the
  server without cloud escrow, or memory-only, chosen at setup: "Generate a key for me" or "I'll maintain my own key");
  BYO bucket or managed Wasabi.

Base branch: local `master/frameleaf-implementation` (`7fc421e533` at planning time; PR 140's pushed head
is `f6d757f36d`). Refetch before every worktree. Mobile (`mobile/`) is untouched; server APIs stay mobile-ready.

## 3. Architecture

```
Self-hosted (AGPL fork)                              Frameleaf Cloud (proprietary, frameleaf-cloud repo)
──────────────────────                               ──────────────────────────────────────────────────
api worker ── FrameleafCloudService ──HTTPS──▶ api.frameleaf.cloud  (instances, entitlements, wallet, remote CP, backup grants)
            ── FrameleafAuthService  ──OIDC───▶ id.frameleaf.cloud   (oidc-provider + Better Auth; instance-access gate)
            ── CloudMlService        ──jobs───▶ ml.<region>.frameleaf.cloud (gateway/broker) ──▶ serverless GPU workers (≤ 5 per job)
microservices ── CloudBackupService ── S3 + SSE-C (per-bucket key) ──▶ Wasabi (one bucket per server; BYO or managed)
edge worker (new) ── ACME DNS-01 ──▶ api (TXT set/remove) ; ── tunnel ──▶ {eu1,us1}.relays.frameleaf.cloud (Go, blind SNI)
                  ── HTTPS listener :2443 (LAN/WAN direct, UPnP/PCP mapping) ── proxies to 127.0.0.1:2283 with X-Forwarded-* + X-Frameleaf-Via
clients: web (served by the instance), native apps: /.well-known/immich, /server/connections, resources API ── race LAN > WAN > relay
DNS: PowerDNS (LUA A/AAAA synthesis, TXT API, CAA) for frameleaf-direct.net
```

Trust boundaries: the relay sees SNI, bytes and truncated IPs only; the cloud never holds instance
passwords, media, TLS keys or backup keys; the instance never holds cloud passwords; services check
entitlements themselves (the certificate on the instance is for UI/gating only). Everything is off until
the admin links (no outbound call before opt-in; `FRAMELEAF_CLOUD_URL` is deployment config).

## 4. Contracts (instance ↔ cloud), condensed

Full DTO tables are in Workstreams A/B; `packages/contracts` (Zod 4 + golden fixtures) is the single source
both repos test against.

- **Discovery** `GET https://api.frameleaf.cloud/.well-known/frameleaf-services` → `{version, validFor:86400, issuer, api, ml:{eu,na}, endpoints{heartbeat,commands,entitlements,licenseRefresh,relayToken,dnsTxt,backupGrant,mlGrant}, jwks{oidc,keys}, regions[], intervals{heartbeatSec:300, entitlementRefreshSec:86400, relayTokenRefreshPct:50}, limits}`; `GET /v1/discovery` (instance auth) adds per-instance service statuses + entitlements.
- **Link** (RFC 8628 from the admin UI): `POST id./device/auth` (client `frameleaf-link`, `instance_name/version/jkt/platform`) → user code `XXXX-XXXX` (BCDFGHJKLMNPQRSTVWXZ), `verification_uri_complete`, 600 s, interval 5; approval page shows server name, version, key fingerprint, IP locale; step-up required; `POST /token` device grant → 10-min link token → `POST api./v1/instances {name, version, platform, jwk, bootId, capabilities, permissions}` → `{instanceId, oidc:{issuer, clientId=instanceId, initialAccessToken (once), registrationEndpoint, scope:"openid email profile", roleClaim:"frameleaf_role", storageLabelClaim:""}, services, owner}`; instance then `POST id./reg` (DCR, `private_key_jwt`, redirect URIs on the relay origin: `/auth/login`, `/user-settings`, `/link`, `/api/oauth/mobile-redirect`, `frameleaf-auth:///oauth-callback`). Headless: `FRAMELEAF_LINK_TOKEN=fll_…` (single use, ≤1 h) as `X-Frameleaf-Link-Token`.
- **Tokens**: `client_credentials` + `client_assertion` (EdDSA, `iss=sub=client_id=instanceId`, `aud=https://id.frameleaf.cloud/token`, `jti`, `exp≤5 min`, `kid`) + `resource=` → JWT 10 min, `scope:"instance"`. Key rotation `GET /v1/instance/keys/nonce` + `POST /v1/instance/keys/rotate {newJwk, proof}` (old key retiring 24 h).
- **Heartbeat** `POST /v1/instance/heartbeat` every 5 min `{version, bootId, uptimeSec, health, endpoints[≤16], remoteAccess, permissions, licenseKid}` → `{commands[], entitlementsChanged, servicesChanged, nextHeartbeatSec, cloneSuspected, notices[]}`; commands `remote.enable|remote.disable|backup.run|secret.rotate|key.rotate|relink`, honoured only if the instance-side permission flag allows; `POST /v1/instance/commands/:id/ack`. Clone rule: ≥3 alternations between two `bootId`s in 30 min → `clone_suspected` (owner email, backup grant refused).
- **Claims to instances** (id token + userinfo): `sub` (account UUIDv7), `email`, `email_verified`, `name`, `picture?`, `frameleaf_role` (`admin` for owner/admin else `user`), `frameleaf_access`, `sid`, `auth_time`. Prompt `instance-access` runs on **every** authorization: `email_verified`, `instance_access(account, client_id)` (owner implicit), account/instance status; consent stored once, access check never skipped. Back-channel logout on unshare/unlink/suspend.
- **License certificate** (JWS EdDSA, `typ:"license+jwt"`, `kid`): `{iss, aud:"frameleaf-server", sub:<account>, iid:<instance>, cnf:{jkt}?, lic:{id,last4,kind}?, ent:["CLOUD","REMOTE_ACCESS","CLOUD_BACKUP","CLOUD_ML","SUPPORTER_SERVER"|"SUPPORTER_INDIVIDUAL"], lim:{relay_mbps:8, relay_gb_month:200, backup_bytes:1e12, instances:3}, lic_exp (period end + 3 d; null lifetime), upd:{after:86400,url}, grace_days:7|14, iat, nbf, exp:+7d, jti}`. Endpoints: `POST /v1/licenses/activate {key, fingerprint:{instanceId, jkt?}, instanceName}` (instance or public rate-limited, air-gapped browser page returns the file), `POST /v1/licenses/refresh`, `POST /v1/licenses/deactivate`, `GET /v1/entitlements`, JWKS `GET /.well-known/frameleaf-keys.json`. Key format `FL-KXXX-XXXX-XXXX` (`K`=S|I, alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, mod-32 check symbol; cloud stores sha256 + last4; shown once).
- **Relay**: `POST /v1/remote/enroll` → `{label, domain, names{relay, lanPattern, ipv6Pattern}, relay{id,host,port:443}, caa{issue, validationMethods:"dns-01", accountUri}, certProfile:"tlsserver", renewBeforeDays:25}`; `PUT/DELETE /v1/remote/dns/txt {name:"_acme-challenge.<label>", value}` (waits ≤25 s for both NS); `PUT /v1/remote/caa`; `GET /v1/remote/relays/candidates` + `POST /v1/remote/relays/select {measurements}`; `POST /v1/remote/relay-token` → `{token (JWS relay+jwt: sub=instance, sni, relay, cnf.jwk, thr{bps,burst}, lim{conns}, exp +4 h), relay{host, sni:"tun.<relay>", alpn:"fl-tunnel/1"}, refreshAfterSec:7200, throttling, limits, keepaliveSec:30}`; `POST /v1/remote/certs` (CT baseline); `GET /v1/remote/usage`. Relay internal: `/internal/relay/{jwks,denylist,throttles,metering,heartbeat,events}`.
- **Backup grant** `POST /v1/backup/grant` → `{provider:"wasabi", region, endpoint, bucket:"fl-<region>-<instanceId>" (dedicated, created for this instance), credentials{accessKeyId, secretAccessKey (once)} scoped to that bucket only, expiresAt:+90 d, rotateAfterSec, quotaBytes, readOnly, versioning:true, sseC:{required:true, algorithm:"AES256"}, policy{denies:["s3:DeleteObjectVersion","s3:PutBucketVersioning","s3:DeleteBucket"]}}`; `/grant/rotate`, `/usage` (per-bucket utilization), `/runs`, `PUT/GET /escrow {version, kdf, cipher, nonce, ciphertext}` (server-key mode only, optional), `/purge` (30-d hold, deletes the bucket). The cloud never receives the bucket key; it can list object names and sizes only.
- **Cloud ML v2** (regional host from discovery, bearer JWT `aud=ml`): `GET /ping` (public), `GET /capabilities` → `{protocol:"frameleaf-cloud-v2", region, workloads[] (only what can run now: entitled+consented+balance>0), consent{requiredVersion, recordedVersion, features{identityNames,medicalSignals,ocrAddon}}, entitlement, wallet{balanceUsd, heldUsd, dailyCapUsd, spentTodayUsd}, limits, catalogEtag}`, `GET /hardware` (synthetic CUDA so `readinessOf()` = model-ready), `GET /v2/catalog`, `POST /v2/estimates` → `{estimateId, expiresAt:+15 min, modelFingerprint, gpuClass, cost{p50,p90,startup,hold,minimum}, seconds{coldStart,run}, basis:"measured|modelled"}`, `POST /v2/jobs` (`Idempotency-Key`; `estimateId, workload, modelId, modelFingerprint, clientRef, packKey, deadlineSeconds, inputs[{inputId, contentType, bytes, sha256}], request`) → `{jobId, status:"awaiting_upload", hold, uploads[{inputId, method:"multipart", partBytes:8388608, parts[], completeUrl, inline}]}`, `POST /v2/jobs/{id}/start`, `GET /v2/jobs/{id}` (ETag/Retry-After; `progress`, `run`, `charges{meteredUsd,holdUsd,ceilingUsd}`, `result{outputs[{url,sha256,bytes}], model{…fingerprint}, timing}`, `purgeAfter`), `POST /v2/jobs/{id}/cancel`, `DELETE /v2/jobs/{id}` (ack → purge), `GET /v2/wallet`, `GET /v2/usage`, `GET /v2/consent/current`, `POST /v2/consent`. Error envelope `{code, message, retryable, refusal, detail, requestId}`; mapping: 401 invalid-key→DestinationUnhealthy, 403 consent-*→ConsentMissing/ConsentVersionOutdated, 402 insufficient-credits/daily-cap→BudgetExceeded/WalletInsufficient, 409 model-mismatch/retired/estimate-expired→ModelMismatch, 429→QuotaExceeded, 503 capacity/region→DestinationUnhealthy (never fallback).
- **Wallet flow**: `startup` = start fee × planned workers (chunked video uses up to 5); hold = ceil(p90Run × 1.25) + startup, sized from the p90 estimate including start fees; metering starts at model-ready, seconds round up; at ≥90 % of hold extend by 25 % from free balance; ceiling = hold + 10 % grace (absorbed by us); over ceiling → cancel at next safe point (`cancelled_budget`, completed outputs delivered); complete → charge = max(min, Σ start fees + metered seconds × class rate) ≤ ceiling (min = one start fee), refund rest; our/provider failure → full refund incl. startup; user cancel/their failure → charge to that point (min charge). Ledger append-only (`top_up|hold|capture|release|refund|adjustment|bonus|expiry|chargeback`), `posted ≥ 0`, `held = Σ open holds`; hard kill at model max runtime.
- **Via header contract** (edge → API over loopback): `X-Forwarded-For/Proto/Host`, `X-Frameleaf-Via: lan|wan|relay`, `X-Frameleaf-Via-Auth: ${FRAMELEAF_EDGE_SECRET}` (per-boot secret generated by the supervisor); API strips client-supplied `X-Frameleaf-*`.
- **Unlink propagation**: instance revoked → OIDC client deleted + back-channel logout (immediate), token endpoint `invalid_client`, relay denylist (≤2 min), Wasabi keys deleted (≤1 min; data read-only 30 d then purge ≤90 d), ML tokens refused, DNS removed after 24 h grace, audit + owner email.

## 10. Assumptions and open owner items (defaults apply until changed)

1. API keys over the relay pass only when the key owner's local user is linked to a Frameleaf account.
2. Anyone the cloud authorizes for an instance is auto-created on that instance (cloud = access authority for
   remote users); admins manage sharing on the account site.
3. `/buy` shows bundled price snapshots (no outbound call before opt-in); the store link opens in a new tab.
4. Background cloud descriptions run only with `autoBatch` on and a daily USD budget (default off).
5. Individual supporter keys bind to `sha256(instanceId+userId)`, one active activation per key.
6. Wallet: USD display, default cap $200 (new accounts) / $1,000 after 90 days; credits expire 12 months after
   purchase (verify consumer law); refunds of unused balance on request (payment fees are not returned); daily spend
   cap $20 by default; top-ups $20 minimum, $25 default, presets $25 / $50 / $100; **no pack bonuses** (a bonus
   would cut into the per-run 100 % floor; any later bonus needs an owner decision and a matching rate change).
7. Subscription price points and included limits (`relay_mbps 8`, `relay_gb_month 200`, `backup_bytes 1 TB`,
   `instances 3`) are placeholders for the owner to set before M3.
8. Transactional email: Resend (EU region); status page Gatus.
9. Warm ML preview tier off at launch: serverless only with `workersMin=0` and no always-on workers, so any warm tier needs
   a new owner decision.
10. Studio exports render locally only, on this server or a LAN worker (owner decision 2026-09-25); there is no cloud
    Studio render workload or render bridge. Smooth motion interpolation at export may still use Frameleaf Cloud as its
    own job.
11. `hfToken` is removed with the previous GPU-provider integration's section unless the local ML image needs it for gated downloads.
12. Canadian customers land on `na` with disclosure until a `ca` region exists.
13. Backup escrow (server-key mode only) is off by default; own-key modes are never escrowed.
14. Managed buckets are named `fl-<region>-<instanceId>`; Wasabi's per-account bucket limit (default is
    believed to be 1,000; verify with Wasabi) is raised before public launch.
15. A bucket that fails the SSE-C capability probe (a `PUT` with customer-key headers rejected) is refused at
    setup; BYO providers must support SSE-C.
16. Cloud ML pricing uses the 2026-09-25 research values (serverless rates, cold-start p50/p90, planning throughput);
    rates, overhead factors, cold starts and throughput are re-measured monthly, and changes apply only to jobs not
    yet started.
17. InsightFace (decided 2026-09-25): Frameleaf buys InsightFace's commercial licence before a paid launch; `buffalo_l`
    stays the default local face model (`antelopev2` optional); faces never go to Frameleaf Cloud.
