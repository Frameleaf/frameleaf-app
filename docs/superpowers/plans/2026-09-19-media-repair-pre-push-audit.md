# Media repair suite: pre-push audit — 2026-09-19

The audit found release-blocking defects that the initial implementation checks did not catch. This report records the corrections and their local verification. The review covers media-health scanning and Locate, transactional relinking, iCloud download/staging/recovery, native Stacks and Live Photos, album/metadata provenance, and fork-to-official return handling.

Reviewed implementation: `ebe9c4a85`, with documentation at `a67a448fb`, compared with the pre-feature base `a9a15a483`. The audit fixes follow those commits. No push, GitHub Actions run, deployment, live Apple-account sync, or production orphan-file operation was performed.

Two additional defects were caught by the independent review of the fixes themselves:

- **P1: pool exhaustion.** A relink transaction's verification callback acquired another database connection. A real PostgreSQL pool with `max: 1` reproduced the blocked callback. It now reads only file bytes; the transaction verifies the already locked database identity. The service regression checks that the callback performs no second database read.
- **P2: legacy physical digests.** Valid shared physical-file records can contain content SHA-1. Requiring SHA-256 would reject those candidates. The guard accepts either verified content digest while retaining size checks and preserving shared metadata; active and dual-write fixtures cover this compatibility case.

## Verification and evidence limits

- The full focused server run passed **164 tests across 12 files**. After the callback change, the **50-test Media Health suite** passed again.
- The seven iCloud/recovery PostgreSQL suites passed **79 tests**. The transactional relink suite passed **19 tests**, including the final legacy-digest compatibility extension: **98 PostgreSQL tests across eight files** in total.
- Server TypeScript and the Nest production build passed.
- The six iCloud Svelte component tests passed.
- Go bridge race tests and `go vet` passed.
- Changed server files passed ESLint and Prettier checks. Documentation links and `git diff --check` passed.
- GitNexus was refreshed against this checkout. Per-method impact checks preceded changes, and independent reviewers checked the pipeline, recovery, schema/relations, and final relink changes. Final delta reviews found no remaining actionable blocker within their reviewed scope. Change detection reported medium aggregate risk and the two expected bridge download flows; this is not proof that every runtime dependency is indexed.

The PostgreSQL checks use PostgreSQL 16 at `127.0.0.1:55491`, isolated databases cloned from an empty local template, and the repository's existing test utilities. They exercise actual SQL and transactions with focused schemas. They do **not** establish that a complete production migration or handoff succeeded. The existing full-schema Media Health suite was adapted for the new API but was not run against that empty template.

The original fixture gaps mattered: simple Apple records hid the parser defect, a fabricated album owner column hid invalid SQL, and successful decoding did not prove content identity. Passing these local checks is not live provider or production acceptance.

## Remaining operator acceptance

- Verify live Apple authentication/device approval, inventory, download, restart/resume, and repair on an operator account. Synthetic protocol fixtures do not prove live Apple compatibility.
- Verify a recovered original retains its asset ID, albums, and other associations, then open its native Stack and original Live Photo still/movie pair. Edited Live Photo pairing and special Apple edit rendering remain unsupported.
- Reconcile the reported production count discrepancy and the 40,000-plus orphaned originals, transcodes, and XMP files using actual database/path evidence. Different counters use different scopes; this audit does not establish the cause of that particular production discrepancy.
- Keep `reserved_import_content_match` for administrator review. Retry alone cannot change that reservation. No retained recovery copy is automatically discarded to resolve it.
