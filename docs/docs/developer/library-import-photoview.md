# Photoview import qualification

The Photoview adapter is under development. The internal SQLite reader does not create destination users, transfer files or expose migration support. All ten source families must pass combined qualification before the expanded feature releases.

## Pinned native evidence

The source is Photoview `v2.4.0`, commit `f79d379e38241c687c55e9f899e30661fd9f115a`. The official image index is `viktorstrate/photoview@sha256:f914c44b202fc8175e09bd56f35bb1a4a7c04dc451652306f240aabc3eea133e`; the qualified lab used its Linux ARM64 image `sha256:a2216ed2ba7423121f5eee8b36e4fd016975e62821245c8d384ed11c988fa1b4`. Publisher BuildKit provenance for ARM64 records the exact source repository and commit, with build completion on 2024-06-23. The application's stopped database records SQLite writer version `3.45.1` in its original header. The earlier `3.40.1` value identifies the separate snapshot helper, not the application writer. This agrees with the pinned [Go SQLite dependency](https://github.com/photoview/photoview/blob/f79d379e38241c687c55e9f899e30661fd9f115a/api/go.mod) and its [embedded SQLite version](https://github.com/mattn/go-sqlite3/blob/v1.14.22/sqlite3-binding.h).

The hosted native qualification job reproduces the four-user directory grants, private-media denials, per-user favourites and protected/unprotected share assertions through the application API. After stopping the source with restart disabled, it checks the original database writer header before the product's consistent SQLite snapshot capture. It compares the product reader's access expansion against the independently observed API inventory, verifies all four compatible account passwords through the destination verifier, and independently hashes generated originals. Cleanup removes only this run's labelled container, newly pulled unused image and private staging files, including cancellation. This stage does not establish destination migration, complete metadata/face coverage, other database engines, Manager browser acceptance or combined ten-source qualification.

The unmodified application ran native GORM migrations and scanned exclusively generated PNGs. Its API created four synthetic users, separate private roots and a shared root assigned to Alice and Bob. Native API assertions verified two media accessible to Alice, two to Bob and none to Mallory; their shared photo has one source ID. Setting Alice's favourite on that photo leaves Bob's favourite false. Attempts by Bob and Mallory to fetch Alice's private photo receive the source's record-not-found error. Native API-created password-protected and unprotected public shares retain distinct non-secret protection flags. The initial concurrent scan encountered SQLite write contention; sequential native scans completed the inventory.

The application was stopped with restart disabled before capturing its database and any WAL, followed by a native SQLite backup. Integrity and foreign-key checks passed. The schema contains 14 application tables, plus SQLite's sequence table; its original 39 schema objects fingerprint as `d6dd07880bb4ee9eee48052a42ed394dd3e33dab75f2f0476c21d9f556871952`. The product reader matched all 41 captured projected content records. Fixtures contain structural definitions and synthetic allowlisted records; the upstream AGPL license accompanies them.

Fresh native installations can emit the same pinned foreign-key and uniqueness clauses in different orders, including swapping the two uniqueness constraints on media paths. Admission permits only permutations of those exact known clauses with every other schema object, column, constraint and SQL fragment unchanged. Missing, duplicated, altered or additional constraints still fail. Each admitted snapshot retains its actual raw schema fingerprint in the reader and manifest binding; normalization never replaces that identity with the fixture hash.

## Reader and preservation matrix

`openPhotoviewSnapshot` admits only the pinned version and exact schema, reads within one read-only transaction, rejects broken declared foreign keys and streams at most 1,000 records per batch. Integer identities remain `bigint`, including composite-key association records. Source binary identity, stopped-writer evidence, semantic relationships not enforced by native foreign keys, effective access and original-file integrity remain separate caller obligations. Photoview does not persist a numbered migration inventory: schema identity cannot prove application identity.

| Source data                            | Reader behavior                                                                                                            | Destination requirement                                                                    |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Media and original paths               | Retain source ID, album ID, recorded path and sidecar path                                                                 | Map actual mounted originals; verify bytes independently; never substitute cached URLs     |
| Directory albums and hierarchy         | Retain albums, parent links and user-album assignments                                                                     | Preserve folders and prove inherited access; require explicit ownership mapping            |
| Favourites                             | Retain separate user/media associations                                                                                    | Preserve each user's state without assigning it to every viewer                            |
| Dates and EXIF                         | Retain shot dates, source metadata and orientation                                                                         | Qualify timezone/manual precedence and geometry before conversion                          |
| Named people and face rectangles       | Retain groups, labels, relationships and rectangles; exclude descriptors                                                   | Qualify original/thumbnail dimensions and orientation; regenerate embeddings               |
| Video metadata and rendition inventory | Retain descriptive fields and rendition purpose/size; exclude generated cache names                                        | Verify originals separately and regenerate previews/transcodes                             |
| Public sharing                         | Retain source owner, album/media references and expiry and whether a password is required; exclude bearer values/passwords | Recreate only equivalent or stricter access; issue new links separately                    |
| Credentials and sessions               | Exclude user passwords and access-token records                                                                            | Preserve qualified passwords through the protected credential channel; claims are fallback |

`Media.PathHash` and album path hashes are MD5 hashes of paths, not content. `Media.Path` is the original; `MediaURL` entries can point to previews or transcoded video. Source albums have a many-to-many user relationship rather than one authoritative owner. A shared source photo therefore requires an explicit destination owner decision and independently preserved access; matching email or taking the first user is insufficient. See the pinned [media model](https://github.com/photoview/photoview/blob/f79d379e38241c687c55e9f899e30661fd9f115a/api/graphql/models/media.go) and [user/album access model](https://github.com/photoview/photoview/blob/f79d379e38241c687c55e9f899e30661fd9f115a/api/graphql/models/user.go).

## Inherited access inventory

`normalizePhotoviewAccess` accepts complete credential-free users, albums, media, directory grants and favourite records from the same admitted snapshot. It expands each directory grant through the actual album parent relationships, including overlapping grants, and retains each media record even when no account currently has access. Duplicate records, dangling references and directory cycles refuse the inventory. Traversal is iterative rather than using the application's recursive SQL.

The resulting reader IDs are source access evidence, never destination owners. Administrative status does not add an implicit grant. Per-user true and false favourite records remain separate; a stale preference after access changes does not grant access. Public bearer links are outside this account-access inventory and must remain restricted until their protection and expiry can be represented equivalently. The captured native Alice/Bob/Mallory counts and private-photo denial provide independent expectations for the generated fixture; the shared source photo retains Alice's favourite separately from Bob's state.

This inventory does not assert complete pagination, source fencing, public sharing equivalence, destination permission enforcement or ownership mapping. Missing preference records retain the source's default false state rather than assigning another user's favourite.

## Common manifest mapping

`readPhotoviewManifest` maps the admitted SQLite reader into the existing common import manifest. It requires complete, unchanged, stopped-writer inventory, explicit source-user ownership decisions for every photo and directory album, a source mount prefix and independently hashed original/XMP evidence. Ownership must be supported by the directory's actual inherited source grants; administrative status and another viewer's favourite never establish ownership. Source path hashes and cached rendition paths are not byte evidence. Recorded original rendition sizes are checked when available.

The mapper preserves original names and media types, captions including deliberate empty captions, paired GPS state, the selected owner's favourite and current source capture clocks. Frameleaf's existing writer prepares the resulting assets; the adapter does not write accounts, databases or files. Passwords remain on the reader's existing separate protected credential channel. Generated renditions, blur hashes and face descriptors are not imported.

Source EXIF parsing can tag floating wall clocks as UTC. The mapper retains the source's stored timestamp and wall clock without inventing a regional zone, and reports this uncertainty for review. Destination clocks retain up to six fractional digits; any extra source precision remains in the protected archive and is reported. Current media dates take precedence over older EXIF rows.

Directory albums start owner-only. Mixed-owner directories receive private owner partitions backed by the source access inventory. Source sharing, other viewers' preferences, custom media titles, directory ancestry, people and remaining source-only metadata stay in the protected archive with unacknowledged preservation differences. These differences must be reviewed before activation; face geometry and active directory hierarchy are not yet mapped. Source capture authority, public command registration and the common Manager flow remain separate unfinished work.

## Outstanding acceptance

MariaDB/MySQL and PostgreSQL, source media beyond the generated PNG fixture, named-face geometry, manual metadata, sidecars, complete public/inherited access paths, destination ownership/privacy, byte transfer, archive persistence, recovery, Manager integration and end-to-end migration remain unqualified. The source image reports a Darktable version-check warning; RAW handling needs separate native acceptance. No source compatibility or release claim follows from this reader stage. Protected Unraid shares remain entirely outside qualification and agent access.
