## Interpretation and limits

- Every record emitted by `git status --porcelain=v1 -z --untracked-files=all --ignore-submodules=none` is preserved. Distinct record and path counts expose rare cases where Git reports the same path more than once. Three status snapshots, two full hash passes, and repository identity/remotes must remain stable or generation fails.
- Hashes describe working-tree bytes only. They do not establish correctness, ownership, licensing, acceptance, or readiness to copy a path into a clean worktree.
- `generated-local-artifact` and `local-evidence` are conservative path-based classifications. They remain unaccepted until reviewed.
- Ignored files are intentionally outside Git's reviewable status set and are not inventoried. Submodule dirtiness is reported by Git but nested submodule files are not expanded.
- The accepted baseline identity is resolved from the supplied commit. Clean-checkout evidence is recorded separately because this generator must not mutate or reconstruct the preserved dirty checkout.
