# Library import adapters

The multi-source importer is under development. A schema reader passing its tests does not establish migration support. Keep new adapters internal until all ten source families pass the combined qualification, including private Synology DSM acceptance.

## PhotoPrism SQLite reader

The checked-in structural fixture was generated by the migrations in the official PhotoPrism `261029-963b58c50` ARM64 release, source commit `963b58c5034a45010b3944841f2bcc2e289abadd`. The fixture records the executable version, release archive checksum, container runtime digest, SQLite writer version, schema fingerprint, migrations and upstream AGPL provenance. It contains schema definitions only, with no media, account credentials or database contents.

`captureSqliteSnapshot` captures committed WAL contents through SQLite's backup API and verifies integrity and foreign keys. The caller must first stop source writers and authorize the source and private staging paths. A database backup does not establish consistency with the originals directory. Originals must be inventoried and hashed while source services and restart mechanisms remain fenced.

`openPhotoprismSnapshot` reads that captured snapshot in a read transaction. It refuses unknown versions, schema differences and missing, failed or unfinished migrations. Extraction uses bounded keyset batches and preserves integer identities as `bigint`. Only approved tables and columns are accessible. This reader does not create destination users, transfer files or activate a library.

| Source information                                                            | Extraction                                                                     | Destination preservation requirement                                                                                                    |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Photos, manual titles/captions, dates, locations, private/favourite state     | Source values and provenance fields retained                                   | Map manual fields before regeneration; verify time zones and restrictions                                                               |
| Files, duplicates, primary/sidecar flags, missing/deleted state               | Separate file records retained                                                 | Resolve originals storage independently from generated storage; hash bytes independently; preserve multiple originals and companions    |
| Albums and memberships                                                        | Albums, membership flags/order and filters retained                            | Preserve folder organization; disclose unsupported dynamic albums and hidden/excluded relationships                                     |
| Users and access rules                                                        | Identity, roles, scope, attributes, base paths and permission records retained | Require explicit owner mapping and equivalent or stricter destination access; exclude built-in anonymous principals from human accounts |
| Labels, keywords, subjects and human face markers                             | Source records and geometry retained                                           | Verify geometry/orientation before creating named faces; regenerate embeddings                                                          |
| Camera, lens, place and detailed metadata                                     | Source records retained                                                        | Preserve unsupported fields in the protected migration archive                                                                          |
| Passwords, reset/invite tokens, sessions, API credentials, public link tokens | Excluded                                                                       | Never migrate or log these values                                                                                                       |
| Model embeddings and generated renditions                                     | Excluded from transfer                                                         | Regenerate from verified originals                                                                                                      |

Do not infer ownership from directory names, email matches or `created_by` alone. The pinned application's CLI indexer produces photos with an empty creator. Global library ownership therefore needs explicit operator mapping, with base-path and role restrictions assessed separately. A path hash or PhotoPrism's own file hash is not the independent migration checksum.

The `261029-metadata.json` fixture records a synthetic photo and private manual album after supported API edits, together with the API's independently read-back metadata. Source photo normalization preserves manual values and provenance, keeps the encoded local wall time separate from the capture instant, and flags `Local` time zones and unknown capture times for review. PhotoPrism's computed quality score is not a user rating. An archived photo has `deleted_at` set and quality greater than `-1`; removed photos have a negative quality score. Private state remains separate from either state. Album normalization retains membership order and hidden/missing flags; excluded relationships are not revived. Folder and filtered albums require explicit membership materialization.

The `261029-files.json` fixture includes two generated synthetic PNG originals indexed by the pinned application, their source records and independent SHA-256 checksums. File classification treats the source root `/` as the originals storage identifier, with paths relative to an explicitly configured library root. Files in the `sidecar` storage tree are regenerable renditions, even when marked primary. Non-primary originals and original-tree sidecars remain separate records. Unsafe relative paths, unqualified storage roots and missing or watermarked originals are refused. Source file hashes are retained only in the archive; they do not supply the migration checksum. Classification does not resolve paths, hash live files or authorize a transfer.

`readPhotoprismInventory` streams logical photos, physical files, album headers, memberships and source principals separately. It uses the captured database for indexed detail lookups and relationship checks, rather than collecting a library-sized lookup map in memory. Before emitting records, it checks both photo identifiers on files, orphan details and memberships, active album references and the presence of an original for each logical photo. Historical hidden/missing membership references remain excluded records. Consumers must close the iterator if they stop early; completion, refusal and iterator return close the source transaction. Credential-free source rows are emitted separately for a future protected migration archive, preserving SQLite scalar types. The synthetic `261029-records.json` fixture was extracted using the same table/column allowlist.

The two built-in anonymous principals are identified by pinned IDs and checked against their expected provider, role and login state. They are separate from human account candidates. Source creator IDs remain provenance, not inferred ownership. Email matches never merge source principals. Inventory extraction does not establish owner mappings, independent byte integrity or permission equivalence, and does not create destination accounts or sharing.

Qualification remains incomplete. Synthetic SQLite originals, API-edited metadata and a private manual album have been exercised. Multi-user role fixtures require an appropriately licensed source installation; additional account roles in the pinned binary refuse setup without membership. No licensing restriction is bypassed. MariaDB, destination mapping, complete preservation, rollback and combined acceptance remain unqualified.
