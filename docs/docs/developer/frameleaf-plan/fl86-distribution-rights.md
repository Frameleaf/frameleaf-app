# Implemented artifact boundary

`studio/tools/engine.mjs attest` now creates `studio/engine/dist/attribution/` before computing the output inventory. It contains the exact notice bytes and an `index.json` identifying their source, hashes, installed runtime packages, resource decisions and unresolved embedded components. The build receipt records the attribution index digest and missing-package-notice list. The original build provenance, lockfile declarations and three embedded receipt notices remain preserved.

`studio/tools/engine.mjs audit-attribution` independently recomputes the expected output from the maintained manifest, retained evidence and installed locked packages. It reads the actual output files, rejecting missing/modified/additional notice files, changed inventory, substituted package versions and symlinked notice paths. It does not repair output during audit. Packaging validates inputs before replacing its own generated attribution directory. The original notice-only slice changed no vendor bytes or application behavior. The later runtime slice below adds explicit refusals through a versioned patch; the vendor snapshot remains unchanged.

Root-level license/copying/notice/copyright files from every installed non-development lockfile package are copied byte-for-byte. Optional packages absent on the build platform are recorded separately. A declaration without a file remains `missing-notice`; collecting files does not establish that source-offer, modification, linking, patent or embedded-code obligations are satisfied.

# Isolated runtime enforcement candidate

This next slice starts from reviewed `7432c5b7f4c1052a12c6ddd361984b9fb4b95570`. It does not mount Studio in the Frameleaf application or pass VID-090. All 210 resource decisions remain blocked; no production approval, model download, purchased tool or licensing permission is invented.

`studio/patches/0004-resource-admission.patch` gates actual resource use before cache/in-flight/warm-runtime shortcuts. `studio/tools/resource-policy.mjs` generates the worker/public-page policy from the existing audited manifest during engine preparation; it rejects any manifest-only approval. The small shared admission module is copied into the prepared source and MOSS public directory and is bound by the adapted source inventory. Missing or unknown resource IDs fail closed. A local URL, blob, cache hit or installed-package origin does not confer admission.

The patch covers shared ONNX binary/text acquisition; MusicGen, Kokoro, Supertonic and MOSS service initialization; seven model/transcription worker message boundaries; CLAP initialization; RIFE and all three bundled Anime4K variants before readiness/session reuse; Google font use/preload; Lottie browse, GIF preview selection, metadata and renderer creation; direct URL-to-File imports; and headless URL media probing. MOSS's independent public model store, runtime constructor/factory and tokenizer processor are guarded. HTML CSP restricts external connection/module/style/font/image/frame acquisition; the automatic Google font stylesheet/preconnects are removed. The CSP is an acquisition restriction, not a sandbox for hostile same-origin JavaScript.

Ordinary installed package imports remain available. Explicit local File/handle media editing retains its existing boundary. `asset:user-import` is still blocked/unqualified: no complete ownership, project-revision-bound grant, recursive project dependency, expression or user-content licensing admission is claimed. URL imports cannot convert a blocked resource to a File to gain that local-media path. Lottie parsing/use remains denied even when presented as a local file/blob. Existing asset bytes and feature code are retained as release blockers rather than removed from the inventory. Font-dependent content fails explicitly instead of being certified with fallback metrics.

## Browser evidence

`node studio/tools/resource-admission.browser.mjs` runs Chromium against the actual prepared engine's Vite editor and headless entrypoints. The initial regression recorded and aborted Google Fonts plus GitHub startup requests. With enforcement, the pages initialize without external acquisition. Each main browser context intercepts all HTTP requests and aborts any external request or ONNX/binary/font payload attempt, including same-origin payloads, so the refusal tests cannot acquire real model payloads. The separate synthetic-policy context contains only the test byte fixture.

- Editor: 22 actual refusal cases; headless: 23 including URL media probing. Cases include warm CacheStorage, concurrent ONNX requests, preseeded service promise maps, fonts, each bundled weight variant, Lottie metadata/renderer blob inputs and warm export-provider preload/rebuild/render, URL-to-File and blob-to-File relabel attempts.
- Seven actual module workers receive cold and repeated initialization requests and return the policy error before acquisition. These exercise initialization refusal, not successful GPU/CPU backend execution.
- MOSS public host/model store and runtime constructor/factory, the public tokenizer page, and a child iframe refuse use. Tests do not acquire or execute MOSS weights.
- Both editor and headless pages successfully import a real 16×16 PNG File through the existing media service into a disposable OPFS workspace. This is a local-file smoke check, not ownership/rights approval.
- A separate test-only intercepted policy supplies one synthetic approved byte fixture to the actual admission module. Matching bytes pass; tampered bytes, a blob-URL identity and `asset:user-import` relabeling fail. No approved fixture record is generated or shipped in production.

The dev-browser tests disable service workers to isolate realm assertions. Production-page smoke runs separately with service workers allowed. Historical upgrade from a pre-enforcement service worker, every export/preview combination, arbitrary user graph/embedded-resource traversal and complete offline cache lifecycle remain unqualified. Fresh browser refusal does not prove those remaining boundaries.
