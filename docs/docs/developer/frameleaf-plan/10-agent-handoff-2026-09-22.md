## Rules that bind this work

- **Hosted checks only.** Do not run builds, full test suites, bundlers or parallel Node processes on the operator's Mac. Push a branch and let GitHub Actions run. Local verification is limited to reading code, single-file checks and one light Vite dev server for previews. This is recorded in the root `AGENTS.md`.
- **Documentation mirror.** Repository Markdown is authoritative. When a Frameleaf design or process document changes, mirror it to Confluence space FR in the same pass, read the page back, and record the receipt in `docs/docs/developer/frameleaf-plan/confluence-mirror.json`. Adding a mirrored document means also adding it to `REQUIRED_READBACK_SOURCES` in `scripts/frameleaf-documentation-coverage.mjs`, the counts in its test, and the counts in `08-reproducibility.md`; the validator fails closed otherwise.
- **Remotes.** Never push to `origin` or to any upstream repository. Push only to the verified `frameleaf` remote, and only when the owner authorizes it. Do not merge, publish or deploy from this branch.
- **Commits.** Author and committer `AJ Taylor <aj@ajtaylor.net>`, no co-author trailers, the real issue key in the subject, delivery branches named `codex/FL-<n>-<description>`.
- **Product boundaries.** Sensitive and Locked semantics, actor-only duplicate review, album membership on sensitive marking and original-file preservation do not change. Cloud processing is explicit. Product copy never says "fork".

## How to run and review the prototype

```sh
cd design/frameleaf/template
pnpm install --ignore-workspace --frozen-lockfile --ignore-scripts
pnpm dev --port 4174
```

Review path for the September 22 work: open All albums in the rail; open the New menu and create an album with an icon from the chooser; open the Family collection and its album strip; open Settings → Storage & originals → Physical deduplication and press Prepare preview plan; switch the theme and the phone viewport on each. The interaction requirements list the expected behaviour for each.

## What is verified and what is not

- Verified in the browser at desktop and phone width, dark and light: the Albums page in grid and list view, the New menu, the New album dialog with the icon chooser and search, the Family collection page, the Locked PIN cells, the share sheet tiles, the Filter control, the physical deduplication preview with all four sample cases.
- Not verified: hosted test runs, the production build, and any behaviour in the Svelte application. The prototype simulations that production must not copy are listed in the plan.
- Known trade-off: because the chooser can pick any Material icon, the prototype's production bundle would include the whole catalogue. Production should serve the icon list as data instead.
