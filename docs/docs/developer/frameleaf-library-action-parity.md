## Dirty-only additions

The dirty checkout contains routes and components for discovery, classification, culling, documents, enrichment, face review, Library Care, pets, photo tools, preservation, Spaces, Studio, and Takeout. They are absent from the clean baseline. Their presence, prototype tests, or route links must not change a row above to implemented or qualified. Documents, pets, shared spaces (at `/sharing/{spaceId}`) and Studio have since landed as committed routes on the integration branch; the route inventory lists them as implemented in code, not qualified, and that does not change a row above either.

## Release gate

For each replaced screen, record a stable action ID and one of: verified equivalent, approved removal/replacement, retained production route, or blocked. Verify owner, shared collaborator/viewer, public-link, elevated/locked, deleted/offline, feature-disabled, and unavailable-worker contexts where applicable. A rendered control, toast, generated client, or passing build is not action parity.
