## Voice-over (clean)

If you run Immich with Docker Compose, moving to Frameleaf is a change of images. Your photos, database and settings stay exactly where they are.

Before you start, back up the database and your originals. Work in your existing stack folder, and never start a second stack against the same database folder.

Replace docker-compose.yml with the one from a Frameleaf release; it selects the Frameleaf server and machine-learning images. Keep your .env as it is, along with the project name, volume names and any changes you made, such as external library mounts.

Pull the new images and bring the stack up again. Nothing is moved and no database is recreated. Never remove volumes during the switch.

The containers now show frameleaf names. Service names stay the same, so service-based commands keep working; update scripts that use the old container names.

[pause]

Open Frameleaf in the browser and sign in once with your existing admin email and password. There's nothing to register, and everyone else keeps using the library while you finish.

Your library is safe counts what Frameleaf found: items, people, albums and the size of your originals. Every original, album, face and edit is where it was; nothing moves unless you say so.

Under Your account, Keep your local admin is recommended: you sign in exactly as you do today, and can link a Frameleaf account later.

Library check takes a quick look at the file records and counts missing originals and damaged files for Library Care. Keep your current folder layout; changing it moves every original, which can take hours.

Processing estimates how long re-indexing with the new models takes; your library stays usable the whole time. Choose On this server, or Decide later to keep your current results. Jobs only queue when you finish.

After Protection and Privacy, Your people shows that Jamie and Emma skip setup and get a short Set up your account page instead. Then choose Open Frameleaf.

[pause]

On phones, the Immich app keeps working. The Frameleaf mobile app is separate: sign in and choose backup albums again, and back up from only one of the two.

Next up: Timeline, layouts and the grid.

## Production notes

- Naming: this is the one Start-here episode that names Immich as the system being moved from (title, beat 2, beat 13 and the before side of beat 4's SPLIT). Frameleaf is always the product; the outro carries the small "Built on Immich" credit.
- Container switch, from docker/README.md ("Existing installations"): "Changing application images does not require moving media or recreating a database. Preserve the existing Compose project name, .env, upload/database paths, volume names, external-library mounts and database settings. Keep the existing stack directory … Do not start a second stack against the same PostgreSQL directory, and do not use `docker compose down --volumes` during this migration." Service keys (`immich-server`, `immich-machine-learning`, `database`, `redis`), the project name `immich` and `IMMICH_*` keys are retained; displayed container names become `frameleaf_server`, `frameleaf_machine_learning`, `frameleaf_postgres`, `frameleaf_redis`. The README lists the service-based commands shown in beats 5 and 6 (`docker compose pull`, `docker compose up -d`, `docker compose logs immich-server`).
- docker-compose.mdx adds: download Compose and hardware-acceleration files from the same Frameleaf release, and "Existing installations should retain their current .env and storage paths instead of replacing them with the example." If the old stack used `hwaccel.ml.yml` or `hwaccel.transcoding.yml`, replace them from the same release too (not narrated). Keep the database image exactly as the release file sets it; docker/README.md says to preserve pinned PostgreSQL/base images.
- Doc gaps to flag, not narrate: the docs do not say what to do when an existing `.env` pins the version line to an older upstream tag, and they do not list which Immich versions can switch directly. Capture with the version line set as the Frameleaf release bundle sets it, and make no version claims.
- Setup flow labels verified in the build (existing-library flow, 10 steps): "Sign in to finish setting up", "Frameleaf found your existing library. Everyone else can keep using it while you finish setting up.", "Sign in once with your admin password. There's nothing to register.", "Admin email", "Sign in and continue"; "Welcome to Frameleaf. Your library is safe." with the stats "items", "people", "albums", "of originals" and the note "Every original, album, face and edit is exactly where it was. Nothing moves unless you say so."; what's new cards "Studio", "Library Care", "Frameleaf Cloud"; "Your account" with "Keep your local admin" and "Link a Frameleaf account"; "Library check", "{healthy} of {count} items look healthy", "missing originals", "damaged files", "Review in Library Care", "Keep your current folder layout"; "Re-indexing {count} items takes about {hours} h on this server. Either route is acceptable; the gate is shown because it explains itself.

Counters use the capture's real values; "2.7 TB" is the decimal-terabyte display of a library of about 2.42 TiB of originals.

Other accounts are never shown setup; they get the one-time "Set up your account" page (reopenable from the account menu).
