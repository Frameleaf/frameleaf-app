# iCloud Photos bridge protocol v1

The bridge imports `github.com/rclone/rclone/backend/iclouddrive/api` at **v1.75.1**, peeled commit **687d264b689b8c49a67e2e52a8a5e0caa01c04ce** (Go 1.26). It uses real Apple SRP authentication and raw CloudKit read requests, never rclone CLI listing. Cloud photo writes and deletes are not implemented.

All `/v1/*` routes require `Authorization: Bearer <token>`. Read the token from `ICLOUD_BRIDGE_TOKEN_FILE` (default `/run/secrets/icloud_bridge_token`), minimum 32 bytes. HTTPS uses `ICLOUD_BRIDGE_TLS_CERT_FILE` and `ICLOUD_BRIDGE_TLS_KEY_FILE`. Listen defaults to `:9443`; HTTP is permitted only with `ICLOUD_BRIDGE_ALLOW_LOOPBACK_HTTP=true` and an explicit loopback listen address. No request/access logs are emitted. Session values and credentials must never enter URLs, CLI arguments or logs.

`GET /health` returns readiness/version/pinned source. `GET /v1/capabilities` returns the same capabilities included in inventory/auth responses. All successful JSON responses include `version:1`. Errors are `{version:1,error:{code,message}}` with fixed sanitized messages: 400 invalid_request, 401 unauthorized, 409 reauthentication_required/device_approval_required/resource_changed/invalid_change_token, 429 rate_limited, 502 upstream_error. TLS setup failure exits with a fixed message. Unsupported operations return 400 unsupported.

CloudKit/PCS POST errors are classified from HTTP status and exact `serverErrorCode`/`errorCode` fields at the top level or in `zones[]`. HTTP 429 and exact `THROTTLED` return `rate_limited`; exact `CHANGE_TOKEN_EXPIRED` returns `invalid_change_token`. The caller may reset the affected durable inventory cursor with a bounded retry; the bridge does not reset or retry it. Other codes (including `CONFLICT`, `ZONE_NOT_FOUND`, unknown aliases, and malformed fields) remain `upstream_error`. Authentication HTTP statuses retain precedence. No upstream reason, message, request identifier, response body, or retry header is forwarded.

`THROTTLED` is documented in [Apple's CloudKit Web Services error codes](https://developer.apple.com/library/archive/documentation/DataManagement/Conceptual/CloudKitWebServicesReference/ErrorCodes.html) and Apple's CloudKit JS client. `CHANGE_TOKEN_EXPIRED` is the explicitly supported compatibility code for this adapter; the pinned rclone API and that public error-code table do not define it. No additional expiry aliases or numeric native CloudKit errors are inferred. Error tests use synthetic redacted fixtures, not captured live Apple traffic.

`POST /v1/auth`: `{action:"login"|"two-factor"|"device-approval"|"validate", appleId?,password?,code?,session?}`. Returns `{version:1,state:"connected"|"awaiting-2fa"|"awaiting-device-approval"|"reauthentication-required",session,capabilities}`. The opaque session is `{version:1,state,appleId,upstream}`; upstream is rclone's serialized Session. It is authenticated internal transport data; the Immich server must encrypt the **entire** envelope at rest and must never return it to the browser. No password or code is retained. Each device-approval action makes at most one PCS request; no polling. It also accepts a previously connected envelope after an inventory/download `device_approval_required` error. Login requests trusted-device push when needed. SMS workflow is currently unsupported.

`POST /v1/inventory`: `{session,kind:"libraries"|"albums"|"assets"|"changes"|"memberships",library?:{area:"private"|"shared",zoneID:{zoneName,ownerRecordName?,zoneType?}},albumId?,cursor?,limit?:100}`. Returns `{version:1,session,records:[raw Apple objects],nextCursor?,complete,capabilities}`. Cursors are opaque base64url JSON and bound to kind, library and album. For `libraries`, cursor advances private then shared database; records include `area` and raw zone fields. Shared-library failure is surfaced, not treated as empty. Albums use continuation markers and preserve parent IDs. Assets/memberships use one rank page (2*limit raw records), including originals and hidden assets in separate cursor phases; the worker must join CPLAsset/masterRef/CPLMaster across pages in its database. Memberships require albumId. Changes use `moreComing` and a sync-token cursor; the final cursor is also returned when complete, for the next incremental run. Cursor completion is not a snapshot isolation guarantee: reconcile via changes after initial scan. Never key by filename/album display name. Preserve raw envelopes/fields and their versions.

`POST /v1/download`: `{session,library,recordId,resourceKey,expectedFingerprint?}`. Looks up the resource afresh and streams bytes. Go/TypeScript use the same canonical fingerprint fixture to prevent JSONB object-key reordering from creating false changes. Resource keys: resOriginalRes, resOriginalVidComplRes, resOriginalAltRes, resJPEGFullRes, resVidFullRes. Response headers: `X-ICloud-Resource-Fingerprint` (SHA-256 of recursively sorted descriptor JSON, recursively excluding credential/URL/token/expiry keys and URL-bearing strings, using Go JSON HTML escaping), `X-ICloud-Resource-Size`, `X-ICloud-Session` (base64url JSON envelope), Content-Type and Content-Length when known. Signed URLs are never returned. Persist the returned session header before completing the job. Caller owns temporary-file promotion/checksum and must discard incomplete streams. Fingerprint mismatch returns 409 before bytes. No Range/resume support.

CloudKit/PCS requests and downloads use HTTPS Apple/iCloud hostname validation, public-address DNS validation at dial time and per-hop redirect validation. Download requests carry no Apple session cookies. Metadata calls do not follow redirects. Credentials only go through rclone's fixed Apple authentication endpoints. Rclone authentication traffic uses its own HTTP transport; no custom endpoints are accepted. Shared `CMM-*` albums are explicitly unsupported and excluded from supported libraries. Raw edit fields are preserved; rendering/reconstructing adjustment recipes or pairing edited Live Photo resources is unsupported. Live/RAW resources are discoverable in raw fields; consumers must preserve master/asset/resource identities.
