# Durable embedded MP4 subtitle source contract

The first embedded profile is `mp4-h264+mov-text-v1`: MP4/H264, preserve color, 720p, high quality and preserve audio. It explicitly requests one `mov_text` track with language `und`, default disposition 1 and forced disposition 0. The Export choice labels this a default text track. This source change does not activate or qualify a worker. Admission still requires the existing fresh, engine-bound worker session and writer evidence, plus the same session's MP4, AVC, mov_text and exact profile proof.

The server derives cues from the immutable project revision with the existing subtitle-sidecar runtime, including visibility, integer frame range clipping and canonical SRT bytes. A private seal binds revision, manifest, engine, range, source checksum and independently expected decoded cue semantics. Embedded exports render caption items off while retaining ordinary titles and the original graph. The owned worker stream-copies video and any audio into the canonical media artifact and adds the text track; it does not publish a sibling subtitle artifact. Existing burn, off, sidecar and legacy exports retain their existing contracts.

Version 1 conservatively accepts nonempty, plain, nonoverlapping cues that have positive millisecond duration after clipping. It refuses markup delimiters, carriage returns and blank paragraphs before creating a job. These are limits of this implementation's SRT-to-mov_text round-trip contract, not a claim that the container can never represent richer semantics. Styling, overlap, empty-track semantics, other codec/container pairs and the complete FL105 format scope remain open; the producer never strips styling, silently drops captions or changes the requested mode to burn.

Before publication, the server independently probes the embedded stream's codec, language and disposition, extracts SRT through its bounded media-process supervisor, and compares decoded cue text and millisecond boundaries. Existing private lease, output checksum, video/audio policy, rollback and publication checks remain authoritative. Backup reads also rederive the embedded seal from the immutable graph.

The source packet includes initial failing admission tests, focused service/schema/contract and worker failure controls, and bounded CPU mux evidence over preserved historical media. A retained 48-frame historical video passed mov_text/Unicode cue readback, exact rational video packet timestamp and compressed payload comparison, and rgba64le decoded-frame comparison. That artifact contains no audio. The second planned audio case did not execute after a harness logger error; audio mux preservation is unqualified. The historical renderer/API receipts retain their original source bindings. Current browser renderer, complete worker/API publication, process restart and all-format FL105 acceptance are not established by this component evidence.
