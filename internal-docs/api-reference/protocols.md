## Socket.IO client events

The normal API gateway is Socket.IO at path `/api/socket.io`, with **websocket-only** transport. It is not a raw WebSocket JSON API and does not enable long-polling. Authenticate the handshake with supported HTTP credentials; the module passes `client.request.headers`, not an invented `handshake.auth.token` field. Browser same-origin cookies and native bearer headers follow normal auth. Shared-link query credentials are not accepted by this handshake. Production validates browser Origin against server/published names. Invalid connection emits `error` with string `unauthorized`, then disconnects. An accepted client joins account-ID and, when present, session-ID rooms. Room IDs are server-owned; there is no client room-join API in this gateway. [server/src/repositories/websocket.repository.ts:103–149](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/repositories/websocket.repository.ts#L103-L149) [server/src/app.module.ts:90–110](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/app.module.ts#L90-L110) [server/src/services/auth.service.ts:563–600](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/auth.service.ts#L563-L600)

## Cloud workload disclosure and job consent

The source disclosure allowlist covers `enrichment`, `restoration-faithful`, `restoration-creative`, `upscale`, `interpolation` and `studio-ai`; other workloads remain pending disclosure. ## Buddy peer vault protocol (excluded from OpenAPI)

The peer receiver implemented here is `BuddyBackupPeerController`/`BuddyBackupPeerService`; there is no independently named `BuddyReceiver` class in this source tree. Base path is `/api/buddy/v1/vaults/:vaultId`. These are server-to-server encrypted backup transport operations, not end-user local-session APIs. `@Authenticated({public:true})` allows the peer service to apply **its own cryptographic authorization** before consuming bytes. [server/src/controllers/buddy-backup-peer.controller.ts:11–170](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/controllers/buddy-backup-peer.controller.ts#L11-L170)

Vault/snapshot identifiers are lowercase UUID patterns; object IDs are 64 lowercase hexadecimal characters. Object bytes are immutable encrypted blocks. Response cache-control is no-store. Storage exhaustion (quota, disk reserve or ENOSPC) becomes 507 with retained snapshots preserved. ### Capability, DPoP and receipt verification

Each request carries `Authorization: DPoP <Cloud Buddy grant>` and `DPoP: <fresh proof JWT>`. The grant is EdDSA `buddy-grant+jwt`, audience `frameleaf-buddy`, version 1, scoped read/write and bound to pair/vault/source/destination IDs and Ed25519 keys. Lifetime is at most 300 seconds. It is a real JWT distinct from the normal user's opaque session token. The receiver verifies Cloud signing keys/issuer, live pairing state, instance binding, grants and proof before allocating a body. Write needs an active pairing and receiving enabled. Recovery routes accept read-only grants. Cloud revocation checks are attempted, with narrowly handled outage behavior; expiration and local replay rules still apply. [server/src/services/buddy-backup-peer.service.ts:138–243](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/buddy-backup-peer.service.ts#L138-L243) [server/src/utils/frameleaf-buddy.ts:100–126](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/utils/frameleaf-buddy.ts#L100-L126)

DPoP proof fields are strict `jti`, `htm`, `htu`, `iat`, `ath`, optional `nonce`; header is `typ:dpop+jwt`, `alg:EdDSA`, embedded Ed25519 JWK. `htu` excludes URL query/fragment, `ath` is base64url SHA-256 of the grant string, and proof timestamp tolerance is 60 seconds. Source key thumbprint must match `cnf.jkt`. Receiver returns `DPoP-Nonce`; source retries a 401 nonce challenge once with a fresh proof. Do not replay the identical request proof. [server/src/utils/buddy-backup-protocol.ts:24–86](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/utils/buddy-backup-protocol.ts#L24-L86) [server/src/utils/buddy-backup-client.ts:45–101](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/utils/buddy-backup-client.ts#L45-L101)

JSON success is `{data,proof}`; proof is EdDSA `buddy-response+jwt` from the pinned destination key, containing vaultId, grantId, requestId, digest, iat, exp. Digest covers `JSON.stringify(data)` exactly. Binary downloads use the `Buddy-Proof` header over `BuddyVault.receipt(id,bytes)`. Verify the destination proof and request correlation before trusting a reply, even over TLS. Snapshot commit digest is SHA-256 over the exact JSON snapshot bytes; `assertBuddyCommitReceipt` refuses a receipt for a different snapshot. [server/src/services/buddy-backup-peer.service.ts:330–345](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/buddy-backup-peer.service.ts#L330-L345) [server/src/utils/buddy-backup-protocol.ts:7–15](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/utils/buddy-backup-protocol.ts#L7-L15) [server/src/utils/buddy-backup-protocol.ts:88–123](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/utils/buddy-backup-protocol.ts#L88-L123)

`BuddyReceipt` is `{id,bytes,digest}`. `BuddySignedSnapshot` is `{snapshot,signature}`; snapshot contains `version:1`, vaultId, id, sequence, previous (string/null), createdAt, retainUntil, keyVersion, manifest (string[]), and objects (`BuddyReceipt[]`). Use the original serialized/signature scheme rather than reconstructing or sorting a signed snapshot. The Cloud transport contract is copied into `frameleaf-buddy.ts`; its upstream attribution is recorded there but this document pins the local source used. ## Machine-learning FastAPI protocol

The ML container exposes its own unprefixed HTTP routes, separate from the Nest server's OpenAPI and user bearer authentication. At this baseline, five explicit FastAPI path operations exist: GET `/`, `/ping`, `/capabilities`, `/hardware`, and POST `/predict`. Source does not attach the normal Frameleaf user AuthGuard to them. It does apply BearerAuthMiddleware: when FRAMELEAF_ML_AUTH_TOKEN is configured, all paths except normalized / and /ping require that worker bearer token; when unset, middleware authentication is disabled. [machine-learning/immich_ml/main.py:213–287](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/machine-learning/immich_ml/main.py#L213-L287) Keep deployment/network access policy explicit; do not infer anonymous internet availability. [machine-learning/immich_ml/main.py:290–345](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/machine-learning/immich_ml/main.py#L290-L345)

| Route               | Wire behavior                                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| GET `/`             | JSON `{message:"Frameleaf ML"}`                                                                                    |
| GET `/ping`         | Plain text `pong`                                                                                                  |
| GET `/capabilities` | `{protocol:"predict-v1",workloads:["face","clip","ocr","enrichment","pet-recognition"]}`                           |
| GET `/hardware`     | JSON providers, openvinoDeviceIds, torchCudaAvailable, cudaDeviceCount, preferredAcceleration and container report |
| POST `/predict`     | Multipart form `entries` plus `image` file or `text` string; JSON inference result                                 |

`entries` is a JSON-encoded `PipelineRequest`, structurally task → model type → `{modelName,options?}`; allowed task/type/option keys are source schemas, not arbitrary constructor arguments. Registered task/type combinations apply Pydantic option models with extra="forbid", rejecting unknown keys. For an unregistered pair, validate_options passes options through; later model admission can still fail. [machine-learning/immich_ml/schemas.py:245–264](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/machine-learning/immich_ml/schemas.py#L245-L264) Server `MachineLearningRepository` builds the actual request contracts; use these instead of inventing an example CLIP/face schema. If both image and text are supplied, image wins. Missing both is HTTP 400; zero-dimension image is HTTP 400; invalid entries/options is HTTP 422. Response is `InferenceResponse` keyed by model task and optional imageHeight/imageWidth; exact task payloads depend on the selected model. FastAPI errors are a separate `detail`-style protocol, not the Nest server's `{message,errors}` shape. [machine-learning/immich_ml/main.py:182–207](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/machine-learning/immich_ml/main.py#L182-L207) [machine-learning/immich_ml/main.py:383–427](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/machine-learning/immich_ml/main.py#L383-L427) [machine-learning/immich_ml/schemas.py:117–135](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/machine-learning/immich_ml/schemas.py#L117-L135)

## Replacement-local Buddy boot activation

A full-server recovery may explicitly grant `mountService: {roots: [{path, device, inode}]}` for `FRAMELEAF_MEDIA_LOCATION`. This is replacement-local boot authority, not a peer HTTP request or Cloud grant. Roots must be unique canonical absolute directory paths with decimal device/inode strings and exactly match the prepared manifest's storage roots, including its original media root. The effective media location must explicitly equal that root. Finalization checks the live recovery fence and completed journal; ordinary boot requires the ready grant and its retained journal. Both recheck directory identity, symlink safety and replacement identity before activation. A changed or unavailable mount profile refuses activation; it does not remap recovered database paths or establish media integrity. ## iCloud weekly producer boundary

The existing iCloud schedule drives the weekly producer; it adds no separate timer or provider-byte access. ## Render-worker and maintenance service boundaries

Render-worker HTTP operations appear in the normal operation reference but their authorization is service-specific. `admitRenderWorker` trades enrollment secret and conformance evidence for a scoped expiring session. Subsequent claims/heartbeat/progress/checkpoint/input/output calls use `x-frameleaf-worker-session` and claim-bound tokens/grants, not the user's bearer. All are HomeNetworkOnly, including original inputs. `claimRenderOperation` returns 204 when no job is admissible. A `public` OpenAPI operation here means the user guard delegates to worker credential validation. [server/src/controllers/render-worker.controller.ts:227–329](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/controllers/render-worker.controller.ts#L227-L329)

The maintenance worker substitutes its own `MaintenanceWorkerController` for normal runtime operations: ping/config/version, database-backup operations and maintenance status/login/actions. Its guard validates the separate `immich_maintenance_token` cookie carrying the maintenance JWT. ## Service boundaries

Cloud account/API contracts, Cloud push gateway implementation, edge TLS/relay admission and worker binaries have separate authorities. Client integrations must check the configured service's capability and authentication contracts rather than infer deployed behavior from a copied schema.
