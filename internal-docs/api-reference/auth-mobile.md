Most controller routes are under `/api`. `GET /.well-known/immich` and `GET /custom.css` are outside that prefix. Discovery returns `api.endpoint: "/api"` and `frameleaf: {instanceId, publicUrl, signIn}`; an unlinked instance can have `instanceId: null`. ## Session authentication: the bearer is opaque

`login` accepts `LoginCredentialDto` (`email`, `password`, optional `rememberMe`) and returns `LoginResponseDto`, including `accessToken`, account details and onboarding state. The token is generated from 32 random bytes; only SHA-256 of it is stored with the session. Password login, administrator-configured OAuth, and Sign in with Frameleaf all issue this same local session type. It is **not a JWT** and has no client-decodable expiry/claims. The Swagger bearer description calls it `JWT`; the implementation takes precedence. [server/src/utils/session.ts:7–31](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/utils/session.ts#L7-L31) [open-api/immich-openapi-specs.json:50404–50417](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/open-api/immich-openapi-specs.json#L50404-L50417)

```http
POST /api/auth/login
Content-Type: application/json

{"email":"person@example.invalid","password":"<password>","rememberMe":false}
```

```http
GET /api/auth/status
Authorization: Bearer <accessToken from LoginResponseDto>
```

Store the token as a credential. `getAuthStatus` returns `AuthStatusResponseDto` (`password`, `pinCode`, `isElevated`, optional `expiresAt`, `pinExpiresAt`). `validateAccessToken` authenticates the presented credential and returns `{ "authStatus": true }`; it does not exchange a refresh token. `logout` invalidates the calling session, clears authentication cookies and returns `LogoutResponseDto` with `successful` and `redirectUri`. A Cloud/OAuth logout redirect is separate from the already-revoked local session. ### Supported carriers and precedence

The guard resolves credentials in this order; a higher-precedence invalid credential is rejected without falling back to another carrier. Do not combine unrelated credentials.

| Credential       | Header or query/cookie carrier                                                                                                               | Selection                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| Shared-link key  | `x-immich-share-key` or `?key=`                                                                                                              | First; header beats query |
| Shared-link slug | `x-immich-share-slug` or `?slug=`                                                                                                            | Second                    |
| Local session    | `x-immich-user-token`, then `x-immich-session-token`, then `?sessionKey=`, then `Authorization: Bearer …`, then `immich_access_token` cookie | Third, in listed order    |
| API key          | `x-api-key` or `?apiKey=`                                                                                                                    | Last                      |

Carrier names still use `immich`. Shared keys decode from hex when length is exactly 100 characters, otherwise base64url; an expired link returns 401 and `reason: "expired"`. Shared credentials are only admitted on operations marked shared-link capable. API keys are hashed for lookup, and their permission list is checked against the operation permission. The owner's admin flag and resource access checks still apply. A key's permission list does not create ownership of another user's asset. [server/src/services/auth.service.ts:615–643](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/auth.service.ts#L615-L643) [server/src/enum.ts:20–53](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/enum.ts#L20-L53) [server/src/services/auth.service.ts:897–949](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/auth.service.ts#L897-L949)

### Permissions, locked content and remote connections

Generated operations carry the required permission and admin metadata. By default an authenticated operation without an explicit permission requires `all` for an API key; `permission: false` bypasses that API-key permission check only. Service-level access checks, shared-link restrictions and admin rules remain relevant. A `public` annotation can also mean a worker/service checks its own credential: it is not proof of anonymous access. [server/src/middleware/auth.guard.ts:53–80](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/middleware/auth.guard.ts#L53-L80) [server/src/services/auth.service.ts:469–503](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/auth.service.ts#L469-L503)

Requests can refresh elevation within the final five minutes; status reads explicitly do not. `lockAuthSession` removes elevation, PIN changes revoke elevations, and API keys/shared links cannot substitute for a PIN-elevated device session. Treat `on_session_lock` as immediate loss of access and purge protected presentation/cache state. Sensitive media and suppressed people/tags/pets have additional server privacy filters. [server/src/services/auth.service.ts:71–72](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/auth.service.ts#L71-L72) [server/src/services/auth.service.ts:959–1077](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/auth.service.ts#L959-L1077)

## OAuth and mobile sign-in

The administrator's provider uses `startOAuth` and `finishOAuth` under `/api/oauth`. The Frameleaf provider uses `startFrameleafSignIn` and `finishFrameleafSignIn` under `/api/oauth/frameleaf`; they are separate slots.

1. Send `OAuthConfigDto` with `redirectUri`, optional client-generated `state`, and PKCE `codeChallenge` to the appropriate authorize operation. Response `OAuthAuthorizeResponseDto` contains `url`; a browser receives state/verifier cookies.
2. Open that authorization URL in the system/browser authorization flow.
3. Send `OAuthCallbackDto` containing the complete returned callback `url`. A native client supplies its expected `state` and `codeVerifier`; browser flow may use stored cookies. The server requires both state and verifier for the configured OAuth callback and validates the exchange.
4. The result is `LoginResponseDto` with a **local opaque session**. Preserve the selected instance address and identity.

```http
POST /api/oauth/authorize
Content-Type: application/json

{"redirectUri":"frameleaf-auth:///oauth-callback","state":"<random state>","codeChallenge":"<S256 PKCE challenge>"}
```

```http
POST /api/oauth/callback
Content-Type: application/json

{"url":"<complete callback URL>","state":"<same expected state>","codeVerifier":"<PKCE verifier>"}
```

The chosen redirect must be permitted by the configured provider/server; this template does not guarantee every deployment accepts that URI. `redirectOAuthToMobile` uses HTTP 307 to `app.immich:///oauth-callback` and preserves the query. `redirectOAuthToFrameleafMobile` similarly uses `frameleaf-auth:///oauth-callback`. Callback query forwarding does not itself authenticate a session. `logoutOAuth` consumes `OAuthBackchannelLogoutDto` as `application/x-www-form-urlencoded`, verifies the provider's logout token, and revokes matching sid/sub sessions. [server/src/controllers/oauth.controller.ts:28–153](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/controllers/oauth.controller.ts#L28-L153) [server/src/services/auth.service.ts:647–689](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/auth.service.ts#L647-L689) [server/src/dtos/auth.dto.ts:132–160](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/dtos/auth.dto.ts#L132-L160)

For Frameleaf apps, `exchangeFrameleafToken` accepts `FrameleafTokenExchangeDto`: this is a Cloud-issued token deliberately minted for this particular instance, not an arbitrary Cloud bearer. Verification includes issuer, signature, expiry, audience, access claims and single-use/maximum age of two minutes. Refusals return the documented `FrameleafTokenExchangeErrorCode`. `createFrameleafHandoff` can transfer a Sign in with Frameleaf session to another published home address using a single-use one-minute code; `redeemFrameleafHandoff` issues a new local session. Use the DTO reference for exact exchange/handoff fields. ## Mobile JSONL synchronization

`getSyncStream` is `POST /api/sync/stream`, requires a device session and `sync.stream`, and responds 200 with `application/jsonlines+json`. An API key may clear the permission guard but the service still returns 403 `"Sync endpoints cannot be used with API keys"` without a session. Input `SyncStreamDto` is `{types: SyncRequestType[], reset?: boolean}`. This is a streamed response, not an array, SSE, or WebSocket transport. Network reads can split a line or contain many lines; buffer until newline before JSON decoding. [server/src/controllers/sync.controller.ts:24–46](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/controllers/sync.controller.ts#L24-L46) [server/src/services/sync.service.ts:249–259](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/sync.service.ts#L249-L259)

```http
POST /api/sync/stream
Authorization: Bearer <device session>
Content-Type: application/json

{"types":["AssetsV3","AlbumsV3","AlbumSourceLinksV1","PinnedCollectionsV1"]}
```

Each serialized line is exactly `{ "type": <SyncEntityType>, "data": <matching sync schema>, "ack": <opaque string> }` followed by `\n`. Do not build acknowledgements from IDs: `SyncAckV1` lines can use a checkpoint type different from their event type. Even though the implementation currently separates internal cursor fields with `\|`, clients must preserve the received string unchanged. Asset checksums/thumbhashes serialize as base64. `SyncCompleteV1` has `data: {}` and the completion acknowledgement. EOF without completion can be an interrupted/failed stream. [server/src/utils/sync.ts:12–44](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/utils/sync.ts#L12-L44) [server/src/services/sync.service.ts:360–364](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/sync.service.ts#L360-L364)

Apply an event to durable local state **before** acknowledging it. `sendSyncAck` sends `SyncAckSetDto` `{ "acks": ["<received ack>"] }`, maximum 1000 strings, and responds 204. The service currently keeps the last acknowledgement for a given family in a request; it does not choose the greatest cursor. Preserve stream order and never send an older checkpoint after a newer checkpoint for the same family. `getSyncAckV2` (`GET /api/sync/ack/v2`) returns `SyncAckV2Dto[]` for every family, including album-source links. Legacy `getSyncAck` filters those results through a frozen legacy enum and omits new families; it is not complete enough for the new mobile mirror. Checkpoints are session-specific, so do not reuse another session's local checkpoint state. [server/src/controllers/sync.controller.ts:48–90](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/controllers/sync.controller.ts#L48-L90) [server/src/services/sync.service.ts:148–224](https://github.com/Frameleaf/frameleaf-app/blob/0a503215fa351aafbeea57c6d19899a9e943fa88/server/src/services/sync.service.ts#L148-L224)

`SyncResetV1` has `data: {}` and ends the stream. Clear/rebuild the mirror as appropriate and acknowledge the reset; the service then resets session sync progress. `reset: true` also resets progress before deciding whether a reset response is needed. `deleteSyncAck` accepts `SyncAckDeleteDto` with optional `types`; omitted types clears all. ## Mobile uploads and duplicate detection

`uploadAsset` is multipart `POST /api/assets`. Required file part `assetData` must be nonempty, even though the schema declares it optional to accommodate body parsing. `sidecarData` is optional. Required metadata includes `fileCreatedAt` and `fileModifiedAt`; optional `filename`, `isFavorite`, `visibility`, `livePhotoVideoId`, JSON-encoded metadata and duration are described by `AssetMediaCreateDto`. Duration is integer milliseconds; a bounded legacy `hh:mm:ss[.fraction]` string is also accepted. `x-immich-checksum` may carry SHA-256 (preferred) or SHA-1 (legacy), hex/base64. A new upload returns 201; a duplicate returns 200 `AssetMediaResponseDto` with duplicate status. Do not treat every 200 as a newly added item. `checkBulkUpload` uses `AssetBulkUploadCheckDto` with per-item client ID and checksum; its source description still mentions SHA-1 although the DTO permits both digests. ## Push registry and encrypted payloads

`getPushStatus` returns `PushStatusResponseDto` (`available`, nullable reason, encryption algorithms, events, registered). Push requires a linked server. `registerPushDevice` is `PUT /api/push/devices/current` with `PushDeviceRegisterDto`: `platform: "ios"\|"android"`, APNs/FCM `pushToken`, raw X25519 `publicKey` base64url, optional iOS `pushToStartToken`/`apnsEnvironment`, optional `backupDeviceKey` and preferences. It requires a signed-in device session, not an API key. PATCH changes supplied fields only.
