## Address discovery and API boundary

Most controller routes are under `/api`. `GET /.well-known/immich` and `GET /custom.css` are outside that prefix. Discovery returns `api.endpoint: "/api"` and `frameleaf: {instanceId, publicUrl, signIn}`; an unlinked instance can have `instanceId: null`. Use the returned information and the selected connection address rather than inferring a Cloud account token is valid on every server. ## Session authentication: the bearer is opaque

`login` accepts `LoginCredentialDto` (`email`, `password`, optional `rememberMe`) and returns `LoginResponseDto`, including `accessToken`, account details and onboarding state. The token is generated from 32 random bytes; only SHA-256 of it is stored with the session. Password login, administrator-configured OAuth, and Sign in with Frameleaf all issue this same local session type. It is **not a JWT** and has no client-decodable expiry/claims. The Swagger bearer description calls it `JWT`; the implementation takes precedence. [server/src/utils/session.ts:7–31](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/utils/session.ts#L7-L31) [open-api/immich-openapi-specs.json:50355–50368](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/open-api/immich-openapi-specs.json#L50355-L50368)

```http
POST /api/auth/login
Content-Type: application/json

{"email":"person@example.invalid","password":"<password>","rememberMe":false}
```

```http
GET /api/auth/status
Authorization: Bearer <accessToken from LoginResponseDto>
```

Store the token as a credential. `getAuthStatus` returns `AuthStatusResponseDto` (`password`, `pinCode`, `isElevated`, optional `expiresAt`, `pinExpiresAt`). `validateAccessToken` authenticates the presented credential and returns `{ "authStatus": true }`; it does not exchange a refresh token. `logout` invalidates the calling session, clears authentication cookies and returns `LogoutResponseDto` with `successful` and `redirectUri`. A Cloud/OAuth logout redirect is separate from the already-revoked local session. [server/src/controllers/auth.controller.ts:34–174](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/controllers/auth.controller.ts#L34-L174)

### Supported carriers and precedence

The guard resolves credentials in this order; a higher-precedence invalid credential is rejected without falling back to another carrier. Do not combine unrelated credentials.

| Credential       | Header or query/cookie carrier                                                                                                               | Selection                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| Shared-link key  | `x-immich-share-key` or `?key=`                                                                                                              | First; header beats query |
| Shared-link slug | `x-immich-share-slug` or `?slug=`                                                                                                            | Second                    |
| Local session    | `x-immich-user-token`, then `x-immich-session-token`, then `?sessionKey=`, then `Authorization: Bearer …`, then `immich_access_token` cookie | Third, in listed order    |
| API key          | `x-api-key` or `?apiKey=`                                                                                                                    | Last                      |

Carrier names still use `immich`. Shared keys decode from hex when length is exactly 100 characters, otherwise base64url; an expired link returns 401 and `reason: "expired"`. Shared credentials are only admitted on operations marked shared-link capable. API keys are hashed for lookup, and their permission list is checked against the operation permission. The owner's admin flag and resource access checks still apply. A key's permission list does not create ownership of another user's asset. [server/src/services/auth.service.ts:615–643](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/auth.service.ts#L615-L643) [server/src/enum.ts:20–53](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/enum.ts#L20-L53) [server/src/services/auth.service.ts:897–949](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/auth.service.ts#L897-L949)

```http

x-api-key: <API key>
```

Browser login cookies have path `/`, SameSite `lax`, secure according to the request, and HTTP-only access/auth-type cookies. `immich_is_authenticated` is a readable status hint, never the authorization credential. Cookie persistence defaults to 400 days; `rememberMe: false` gives session cookies. This cookie age is not a guaranteed server token lifetime. Token lookup rejects expired rows and deleted users; scheduled cleanup also removes sessions inactive for 90 days. Login/logout emit `Clear-Site-Data: "cache"`. ### Permissions, locked content and remote connections

Generated operations carry the required permission and admin metadata. By default an authenticated operation without an explicit permission requires `all` for an API key; `permission: false` bypasses that API-key permission check only. Service-level access checks, shared-link restrictions and admin rules remain relevant. A `public` annotation can also mean a worker/service checks its own credential: it is not proof of anonymous access. [server/src/middleware/auth.guard.ts:53–80](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/middleware/auth.guard.ts#L53-L80) [server/src/services/auth.service.ts:469–503](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/auth.service.ts#L469-L503)

`unlockAuthSession` accepts `SessionUnlockDto` with the PIN and elevates a real session for 60 minutes. Requests can refresh elevation within the final five minutes; status reads explicitly do not. `lockAuthSession` removes elevation, PIN changes revoke elevations, and API keys/shared links cannot substitute for a PIN-elevated device session. Treat `on_session_lock` as immediate loss of access and purge protected presentation/cache state. Sensitive media and suppressed people/tags/pets have additional server privacy filters. [server/src/services/auth.service.ts:71–72](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/auth.service.ts#L71-L72) [server/src/services/auth.service.ts:959–1077](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/auth.service.ts#L959-L1077)

Remote arrival is attested by the edge worker, using `x-frameleaf-via` (`lan`, `wan`, `relay`) together with its secret. Clients must not set these themselves. A forged/unverified claim returns 403 `frameleaf_via_unverified`; other client-supplied `x-frameleaf-*` claims are stripped except the server-issued render-worker credential. For `wan`/`relay`, sessions generally must be Sign in with Frameleaf sessions; administrators can enable password sessions over remote access. An API key's owner must have a linked Frameleaf account. Shared links can pass this sign-in gate but retain their own authorization. Refusal uses `frameleaf_sign_in_required`. Home-only worker routes reject remote access with `frameleaf_home_network_only`; originals, archives and database backups marked OriginalTransfer are additionally gated over relay by `allowOriginalsOverRelay`. Direct/home access has different policy. ## OAuth and mobile sign-in

The administrator's provider uses `startOAuth` and `finishOAuth` under `/api/oauth`. The Frameleaf provider uses `startFrameleafSignIn` and `finishFrameleafSignIn` under `/api/oauth/frameleaf`; they are separate slots.

1. Send `OAuthConfigDto` with `redirectUri`, optional client-generated `state`, and PKCE `codeChallenge` to the appropriate authorize operation. Response `OAuthAuthorizeResponseDto` contains `url`; a browser receives state/verifier cookies.
2. Open that authorization URL in the system/browser authorization flow.
3. Send `OAuthCallbackDto` containing the complete returned callback `url`. A native client supplies its expected `state` and `codeVerifier`; browser flow may use stored cookies. The server requires both state and verifier for the configured OAuth callback and validates the exchange.
4. The result is `LoginResponseDto` with a **local opaque session**. Preserve the selected instance address and identity.

```http
POST /api/oauth/authorize
Content-Type: application/json

{"redirectUri":"frameleaf-auth:///oauth-callback","state":"<random state>","codeChallenge":"<S256 PKCE challenge>"}
```

```http
POST /api/oauth/callback
Content-Type: application/json

{"url":"<complete callback URL>","state":"<same expected state>","codeVerifier":"<PKCE verifier>"}
```

The chosen redirect must be permitted by the configured provider/server; this template does not guarantee every deployment accepts that URI. `redirectOAuthToMobile` uses HTTP 307 to `app.immich:///oauth-callback` and preserves the query. `redirectOAuthToFrameleafMobile` similarly uses `frameleaf-auth:///oauth-callback`. Callback query forwarding does not itself authenticate a session. `logoutOAuth` consumes `OAuthBackchannelLogoutDto` as `application/x-www-form-urlencoded`, verifies the provider's logout token, and revokes matching sid/sub sessions. [server/src/controllers/oauth.controller.ts:28–153](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/controllers/oauth.controller.ts#L28-L153) [server/src/services/auth.service.ts:647–689](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/auth.service.ts#L647-L689) [server/src/dtos/auth.dto.ts:132–160](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/dtos/auth.dto.ts#L132-L160)

For Frameleaf apps, `exchangeFrameleafToken` accepts `FrameleafTokenExchangeDto`: this is a Cloud-issued token deliberately minted for this particular instance, not an arbitrary Cloud bearer. Verification includes issuer, signature, expiry, audience, access claims and single-use/maximum age of two minutes. Refusals return the documented `FrameleafTokenExchangeErrorCode`. `createFrameleafHandoff` can transfer a Sign in with Frameleaf session to another published home address using a single-use one-minute code; `redeemFrameleafHandoff` issues a new local session. Use the DTO reference for exact exchange/handoff fields. [server/src/controllers/frameleaf-auth.controller.ts:38–152](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/controllers/frameleaf-auth.controller.ts#L38-L152)

## Mobile JSONL synchronization

`getSyncStream` is `POST /api/sync/stream`, requires a device session and `sync.stream`, and responds 200 with `application/jsonlines+json`. An API key may clear the permission guard but the service still returns 403 `"Sync endpoints cannot be used with API keys"` without a session. Input `SyncStreamDto` is `{types: SyncRequestType[], reset?: boolean}`. This is a streamed response, not an array, SSE, or WebSocket transport. Network reads can split a line or contain many lines; buffer until newline before JSON decoding. [server/src/controllers/sync.controller.ts:24–46](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/controllers/sync.controller.ts#L24-L46) [server/src/services/sync.service.ts:249–259](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/sync.service.ts#L249-L259)

```http
POST /api/sync/stream
Authorization: Bearer <device session>
Content-Type: application/json

{"types":["AssetsV3","AlbumsV3","AlbumSourceLinksV1","PinnedCollectionsV1"]}
```

Each serialized line is exactly `{ "type": <SyncEntityType>, "data": <matching sync schema>, "ack": <opaque string> }` followed by `\n`. Do not build acknowledgements from IDs: `SyncAckV1` lines can use a checkpoint type different from their event type. Even though the implementation currently separates internal cursor fields with `\|`, clients must preserve the received string unchanged. Asset checksums/thumbhashes serialize as base64. `SyncCompleteV1` has `data: {}` and the completion acknowledgement. EOF without completion can be an interrupted/failed stream. [server/src/utils/sync.ts:12–44](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/utils/sync.ts#L12-L44) [server/src/services/sync.service.ts:360–364](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/sync.service.ts#L360-L364)

Apply an event to durable local state **before** acknowledging it. `sendSyncAck` sends `SyncAckSetDto` `{ "acks": ["<received ack>"] }`, maximum 1000 strings, and responds 204. The service currently keeps the last acknowledgement for a given family in a request; it does not choose the greatest cursor. Preserve stream order and never send an older checkpoint after a newer checkpoint for the same family. `getSyncAckV2` (`GET /api/sync/ack/v2`) returns `SyncAckV2Dto[]` for every family, including album-source links. Legacy `getSyncAck` filters those results through a frozen legacy enum and omits new families; it is not complete enough for the new mobile mirror. Checkpoints are session-specific, so do not reuse another session's local checkpoint state. [server/src/controllers/sync.controller.ts:48–90](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/controllers/sync.controller.ts#L48-L90) [server/src/services/sync.service.ts:148–224](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/sync.service.ts#L148-L224)

`SyncResetV1` has `data: {}` and ends the stream. Clear/rebuild the mirror as appropriate and acknowledge the reset; the service then resets session sync progress. `reset: true` also resets progress before deciding whether a reset response is needed. `deleteSyncAck` accepts `SyncAckDeleteDto` with optional `types`; omitted types clears all. The server can force a reset when history has aged out or legacy memory cursors lack visibility history. [server/src/services/sync.service.ts:227–282](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/services/sync.service.ts#L227-L282)

## Mobile uploads and duplicate detection

`uploadAsset` is multipart `POST /api/assets`. Required file part `assetData` must be nonempty, even though the schema declares it optional to accommodate body parsing. `sidecarData` is optional. Required metadata includes `fileCreatedAt` and `fileModifiedAt`; optional `filename`, `isFavorite`, `visibility`, `livePhotoVideoId`, JSON-encoded metadata and duration are described by `AssetMediaCreateDto`. Duration is integer milliseconds; a bounded legacy `hh:mm:ss[.fraction]` string is also accepted. `x-immich-checksum` may carry SHA-256 (preferred) or SHA-1 (legacy), hex/base64. A new upload returns 201; a duplicate returns 200 `AssetMediaResponseDto` with duplicate status. Do not treat every 200 as a newly added item. `checkBulkUpload` uses `AssetBulkUploadCheckDto` with per-item client ID and checksum; its source description still mentions SHA-1 although the DTO permits both digests. [server/src/controllers/asset-media.controller.ts:81–120](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/controllers/asset-media.controller.ts#L81-L120) [server/src/dtos/asset-media.dto.ts:34–103](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/dtos/asset-media.dto.ts#L34-L103)

```sh
curl -X POST 'https://server.example.invalid/api/assets' \
  -H 'Authorization: Bearer <session>' \
  -F 'assetData=@/absolute/path/photo.jpg' \
  -F 'fileCreatedAt=2026-10-06T12:00:00.000Z' \
  -F 'fileModifiedAt=2026-10-06T12:00:00.000Z'
```

The resumable `assets/uploads` protocol uses IETF draft 12 / interop version **9**, not tus. `getAssetUploadResourceLimits` (OPTIONS) returns limits; `createAssetUploadResource` (POST) takes raw media bytes and required `Upload-Draft-Interop-Version: 9`, `Upload-Complete: ?0\|?1`, `Repr-Digest: sha-256=:<whole-file padded standard-base64 SHA-256>:` and `Asset-Metadata` (canonical unpadded base64url UTF-8 JSON). Supported metadata includes filename, creation/modification dates, optional duration/favorite/visibility/metadata, optional `publication: "live-photo"` and scoped iCloud `sourceIdentity`; no sidecar or pre-existing asset references. Encoded bodies other than identity are rejected. Configured ceilings are 2 GiB per file, 64 MiB per append, 24-hour age and four active uploads. OPTIONS advertises a storage-capacity snapshot: max-size is at most half the available upload storage, capped by the configured ceiling; max-append-size is at most that max-size. A created resource pins its admitted size limit. These values can shrink and are not a reservation against concurrent writers. Creation or append/assembly storage exhaustion can return 507. ## Push registry and encrypted payloads

`getPushStatus` returns `PushStatusResponseDto` (`available`, nullable reason, encryption algorithms, events, registered). Push requires a linked server. `registerPushDevice` is `PUT /api/push/devices/current` with `PushDeviceRegisterDto`: `platform: "ios"\|"android"`, APNs/FCM `pushToken`, raw X25519 `publicKey` base64url, optional iOS `pushToStartToken`/`apnsEnvironment`, optional `backupDeviceKey` and preferences. ## System notification language

`getMyPreferences` and `updateMyPreferences` expose `notifications: {locale?, devices?: [{sessionId, locale}]}`. Locale is a valid BCP-47 tag of at most 64 characters. Device overrides are keyed by session UUID; the list has at most 100 unique session IDs. Send the complete replacement device list with the last read `expectedRevision` to avoid overwriting another save; stale revisions return 409 without applying changes. The server selects a device override for push, then the account locale, then English. It canonicalizes the selected tag and looks up an exact catalog, with no automatic region/dialect substitution. This source contains only the English catalog; an unsupported locale or unknown/invalid template preserves the supplied fallback text.

System text is rendered by the origin server before per-device push encryption. Preferences are read at delivery, including retries; queued notices do not freeze a language. Origin-only template keys/arguments do not enter `NotificationDto` or the encrypted push payload. Supplied legacy/user text is retained rather than machine-translated. Stored/socket system notifications use the account preference because they have no destination device. Origin templates now also cover reconciliation, memories, partner/album access changes, Studio export completion/failure, backup staleness and Cloud Backup activation; the catalog still contains only English. ## HTTP errors and retry decisions

The global exception filter returns JSON, `X-Correlation-ID` and `Cache-Control: no-store` when it can still write the response. It preserves exception-specific fields but removes duplicate `error` and `statusCode`. The message portion of a typical unauthorized response is `{ "message": "Authentication required" }`; validation retains `{ "message": "Validation failed", "errors": [<Zod issue objects>] }`; an unwrapped unexpected error is 500 with `message: "Internal server error"`. Responses from this filter also include `displayError: {version: 1, code, args, fallback: {locale: "en", message}}`. This is presentation metadata: HTTP status and existing domain fields still govern recovery. Request/response validation use distinct `request_validation_failed`/`response_validation_failed` display codes; other display codes are selected by HTTP status. Only allowlisted nonnegative safe-integer arguments are copied from domain errors. [server/src/utils/server-error-display.ts:1–37](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/utils/server-error-display.ts#L1-L37) The ErrorInterceptor can instead wrap non-HTTP errors with an operation-specific message, so clients must not key retries on that text. [server/src/middleware/error.interceptor.ts:29–39](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/middleware/error.interceptor.ts#L29-L39) Do not assume every error has the same DTO or numeric code field. A streaming failure after headers/bytes are sent may terminate the connection without a replaceable JSON body. [server/src/middleware/global-exception.filter.ts:24–83](https://github.com/Frameleaf/frameleaf-app/blob/24d509f1346e344bb356f92cd0fbed2a59b74ca8/server/src/middleware/global-exception.filter.ts#L24-L83)

| Status/signal                                   | Client action                                                                               |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 400 validation/deprecated sync/invalid metadata | Correct request; do not blindly retry                                                       |
| 401 invalid/expired credential                  | Sign in or renew the relevant credential; shared-link `reason: expired` explains its expiry |
| 403 permission/network/access refusal           | Respect the returned `code` and connection/account policy                                   |
| 409 upload offset/state conflict                | Reconcile HEAD/result for the same resource                                                 |
| 429 `rate_limited`                              | Respect `Retry-After` seconds                                                               |
| 503 rate-counter outage on remote access        | Respect `Retry-After`; home-network policy differs                                          |
| 507 upload/Buddy storage full                          | Preserve snapshots; storage intervention needed                                             |
| JSONL EOF without completion                    | Resume from last durably applied/acknowledged state                                         |

Rate limits are shared in PostgreSQL. Per-route rules and remote media/general ceilings differ; a counter outage can fail remote access closed while permitting home access. Numeric limits are configuration/source contracts, not an invitation for client polling loops.
